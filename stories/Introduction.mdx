# Chatworks component catalog

Composable browser components, not an application shell or backend. These stories
consume the public compiled package and use synthetic, in-memory fixtures. Nothing
connects to a repository, provider, account, or private note store.

## Find a capability

- **Primitives** — attachments, combobox inputs, loading indicators, and notifications.
- **Chat** — turns, message lists, composers (including repository-scope regressions),
  thinking disclosures, tool activity, and session navigation.
- **Repository** — transport-free diff rendering; **Experimental source reading**
  contains the optional commits reader, source annotations, and repository primitives.
  These entries require explicit imports and host-injected clients.
- **Workbench** — independently inspect view mounting, view switching, and commands.
- **Configuration** — settings and provider setup with injected host implementations.
- **Compositions** — chat and a consumer-owned board/canvas workbench. These demonstrate
  composition contracts, not a prescribed product or roadmap.

## Inspect states and interactions

Choose a story, then use **Controls** to adjust inputs. Controls labeled **Fixture**
change synthetic client/registry scenarios, not component properties. Named stories make
loaded, unbound, empty, loading, error, read-only, and bounded states reproducible
where relevant. **Interactions** shows the play assertions; **Accessibility** audits
the actual components, including their shadow roots.

Use the **color scheme** toolbar to inspect light and dark browser defaults and the
**viewport** toolbar to inspect narrow layouts. Host framing is intentionally modest;
component CSS parts remain unskinned. The optional commits reader uses its own public
theme tokens. Hosts own navigation, persistence, authorization, and the meaning of
semantic events. Fixture event output only reports intent—it grants no authority.
